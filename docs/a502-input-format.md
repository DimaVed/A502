# Входной файл A502 / PAN AIR — формат и справочник

Документ описывает **входной deck** (файл `.inp`) оригинальной фортрановской программы
A502 (PAN AIR) так, как его фактически читает код из `fortran/panair.f90`
(PDAS-версия, `versn = 'PDAS version j01, 08 Dec 2020'`).

Источники:

* `fortran/panair.f90` — подпрограммы `inecho` (предобработка карт), `inputa`
  (разбор секций), `inbc`/`inbc1`/`inbc2` (заголовки геометрии и граничные условия),
  `meshp`, `circ`, `ellpt`, `peainp`, `dfnabu`, `trwake` (геометрия);
* `samples/*.inp` — рабочие примеры, `samples/*.out` — их вывод;
* `fortran/readme.txt` — краткое описание дистрибутива.

Документ намеренно описывает **поведение исходника**, в том числе неочевидные
места, которые расходятся с «идеальным» описанием формата.

---

## 1. Как программа читает файл

При запуске A502 просит имя входного файла, читает его с unit 5 и создаёт:

* `panair.out` — основной отчёт;
* `panair.err` — сообщения об ошибках;
* множество рабочих файлов `ftNN`, `rwmsNN` и т.п. (см. `clean502.sh`).

Предобработка `inecho` делает **два прохода** по файлу, после чего `inputa`
разбирает очищенную копию:

1. `inecho` находит `$title`, выводит шапку, затем перечитывает файл и выводит
   список карт до `$end` в отчёт.
2. `inecho` ещё раз перечитывает файл, **вырезает комментарии**, обрабатывает
   директивы повторения `#` и записывает очищенную копию на unit 22.
3. `inputa` читает уже очищенную копию.

Практическое следствие: всё, что описано ниже, относится к картам **после**
вырезания комментариев.

## 2. Синтаксис входного файла

### 2.1. Карты и колонки

* Файл состоит из строк (карт) длиной до 80 символов. Внутри программы карта
  читается в буфер 80 символов; более длинные строки обрезаются.
* Числа в подавляющем большинстве секций читаются **фиксированными полями по
  10 символов** (`E10.0`, `F10.5`, `F10.0`). Значения нужно выравнивать по этим
  полям; произвольная «свободная» запись через пробелы может быть разобрана
  не так, как ожидается.
* В секциях с форматом `F10.x` не используйте экспоненциальную запись —
  пишите обычное десятичное число (`0.6`, `1.0`, `.5`). В геометрических
  препроцессорах используется `E10.0`, там допустимы `1.0E+00`, `1.0D+00`.
* Текстовые поля (имена сетей, материалов) — 10 символов, выровнены влево.

### 2.2. Секции `$...`

Секция начинается картой, у которой `$` стоит **в первой колонке**:

```
$title
$symmetry - xz plane of symmetry
$points - wing body
$end
```

Правила распознавания:

* Значимы **только первые 4 символа** карты, включая `$`.
  `$symmetry`, `$symmetric flow`, `$sym` — это одна и та же секция `$sym`.
* Сравнение идёт с двумя вариантами: **все строчные** или **все заглавные**
  первые 4 символа. Смешанный регистр (`$Sym`) **не распознаётся**.
* Остаток строки после ключевого слова — произвольный текст-описание, он
  игнорируется. Именно поэтому в примерах можно писать
  `$points - defines network geometry...`.
* Неизвестный ключ (первые 4 символа которого нет в словаре `idict`) — фатальная
  ошибка: `following card does not match designated keyword`.
  Зарезервированный `$zzz` — пустая секция-заглушка.

Полный словарь ключей и синонимов — в разделе 4.

### 2.3. Комментарии `=` и `!` — главная ловушка

На этапе `inecho` каждая карта **обрезается по первому символу `=` или `!`**:
всё, начиная с него, заменяется пробелами; пустая карта пропускается.

Из этого следует:

* Строки вида `=amach`, `=kn`, `=x(1,1) y(1,1) z(1,1) ...` — это **только
  подписи для человека**, а не данные. Значения должны идти на следующих картах.
* Символы `=` и `!` нельзя использовать в данных, именах и даже в заголовке:
  всё после них будет потеряно.
* В старых deck'ах встречается значение на строке с `=`:

  ```
  $mach number
  =  0.010000
   0.0
  ```

  Это **не** Mach 0.01: строка `= 0.010000` целиком является комментарием, а
  Mach будет прочитан из следующей строки (`0.0`). Именно так и происходит в
  `samples/ellip.inp` (в `ellip.out` видно `mach number = 0.00000`).

### 2.4. Повторение карт `#`

Карта, начинающаяся с `#`, — директива повторения. Формат:

```
# m n
```

* следующие `n` карт повторяются `m` раз;
* `n` можно опустить — тогда повторяется одна следующая карта;
* сама директива в очищенный поток данных не попадает.

Пример из `samples/nac6.inp`:

```
=bet1(1)  bet1(2)
# 12      1
-.7       -.7
```

означает 12 одинаковых карт `-.7 -.7` (по одной на каждую внутреннюю
расчётную точку сети).

### 2.5. Конец файла — `$end`

Файл должен завершаться секцией `$end` (достаточно первых 4 символов). Карты
после `$end` не обрабатываются. `$end` запускает финальную обработку: подсчёт
сетей, выбор поверхностей для сил, материалов, проверку числа сетей и т.д.

### 2.6. Порядок секций

Жёсткого «оглавления» нет, но исходник накладывает ограничения:

* `$net` (общее число сетей) может находиться в любом месте до `$end`;
  соответствие проверяется в конце разбора.
* `$points`, `$quadrilateral`, `$gothic`, `$circular`, `$elliptical`,
  `$trailing` создают сети; `$trailing` может ссылаться только на уже
  созданную сеть.
* `$cambered` (`$cam`) — не генератор, а **модификатор последней созданной
  сети**: он пересчитывает её `z`-координаты по заданной срединной линии и
  крутке. Обычно ставится сразу после `$quadrilateral`.
* `$abutments` и `$pea` должны идти **после** всей геометрии.
* `$end` — последняя секция.
* Если задано число сетей в `$net`, сумма `kn` по всем секциям-генераторам
  (`$points`, `$quadrilateral`, `$gothic`, `$circular`, `$elliptical`,
  `$trailing`) должна с ним совпадать, иначе — фатальная ошибка.

Рекомендуемый порядок (как в примерах):

1. `$title`
2. `$datacheck` / `$solution`
3. `$restart` (если нужен)
4. `$symmetry`, `$mach`, `$cases`, `$angles`, `$sideslip`, `$reference`
5. `$printout`, `$velocity correction`, `$eat`
6. `$networks` (если хотите контролировать число сетей)
7. геометрия: `$points` / `$quadrilateral` / ... / `$trailing`
8. `$abutments`, `$pea`, `$rearrange`
9. `$materials`, `$forces`, `$sectional`
10. `$flowfield`, `$xyz`, `$grids`, `$streamlines`, `$nwl`
11. `$trefftz`, `$end`

## 3. Числа, имена и идентификаторы сетей

* Номера сетей назначаются **последовательно** в порядке появления
  секций-генераторов. Поле `kn` в заголовке такой секции — это
  **количество сетей в данной секции**, а не номер первой сети. `$cambered`
  новых сетей не добавляет.
* Сети имеют имя до 10 символов, задаваемое в геометрической секции
  (колонки 71–80 соответствующей карты). Имя может быть пустым.
* В разных секциях сеть можно указывать:
  * **именем** (10-символьное поле) — `$abutments`, `$pea`, `$trailing`,
    `$materials`;
  * **номером** (число в 10-символьном поле) — `$forces`, `$sectional`;
  * в `$abutments`/`$pea`/`$trailing`/`$materials` допускается и имя, и
    номер: сначала выполняется поиск по имени, если не найдено — поле
    читается как число.
* Поле `$net` (общее количество сетей) — только контроль количества.
* Имена должны быть уникальны; исходник не проверяет это специально, но
  неоднозначные имена приведут к выбору первой совпавшей сети.

Ограничения программы (из `parameter` в `panair.f90`):

| Что | Предел |
|---|---:|
| Сетей | 150 |
| Точек сетки | 20 000 |
| Панелей | 18 000 |
| Расчётных точек | 24 000 |
| Решений (α/β) | 4 |
| Групп сечений | 5 |
| Сечений в группе | 25 |
| Линий тока | 500 |
| Off-body точек | 1666 |
| `$pea`-спецификаций | 100 |
| Кромок в одной `$pea`-спецификации | 10 |
| Повторяемых строк в `#` | 200 |

## 5. Секции общего описания задачи

### 5.1. `$title`

**Карты:** ровно две строки по 80 символов.

```
$title
Первая строка заголовка
Вторая строка заголовка
```

* Строки читаются как текст; `=` и `!` в них обрезаются.
* Если вторая строка отсутствует, следующая карта (например, `$datacheck`)
  будет прочитана как вторая строка заголовка. Всегда задавайте две строки.

---

### 5.2. `$cases`

**Карта 1:** `nacase` — число одновременных решений, 1…4.

```
$cases
1.
```

По умолчанию `nacase = 1`.

---

### 5.3. `$angles-of-attack` (`$ang`)

**Карта 1:** `alpc` — угол атаки, задающий направление сжимаемости
(обычно совпадает с α первого решения), градусы.

**Карта 2:** `alpha(1) … alpha(nacase)` — углы атаки для каждого решения.

```
$angles-of-attack
=alpc
4.
=alpha(1) alpha(2)  alpha(3)
4.        10.       0.
```

При `nacase = 1` читается только `alpha(1)`.

---

### 5.4. `$sideslip` / `$yaw` (`$sid` / `$yaw`)

Аналогично углам атаки:

**Карта 1:** `betc` — угол скольжения, задающий направление сжимаемости.

**Карта 2:** `beta(1) … beta(nacase)` — углы скольжения для каждого решения.

```
$yaw angles
    0.0000
    0.0000
```

`$yaw` — устаревший синоним `$sideslip`, разбор одинаковый.

---

### 5.5. `$mach` (`$mac`)

**Карта 1:** `amach` — число Маха. По умолчанию 0.

```
$mach number
.6
```

---

### 5.6. `$datacheck` (`$dat`)

**Карта 1:** `ndtchk`, `nprten`.

| Поле | Значение |
|---|---|
| `ndtchk` | 0 — полное решение; 1 — проверка данных (абутменты, BC, нормали); 2 — только абутменты |
| `nprten` | >0 — печатать нормали (по умолчанию 0) |

```
$datacheck
0.
```

`$solution` (`$sol`) не имеет карт данных и сбрасывает `ndtchk` в 0. Если в
файле есть и `$datacheck 1.`, и более поздний `$solution`, программа выполнит
полное решение.

---

### 5.7. `$restart` (`$res`)

**Карта 1:** `nckusp`, `nckaic`, `ifact`.

| Поле | Значение |
|---|---|
| `nckusp` | читать параметры сингулярностей (0/1) |
| `nckaic` | читать AIC: 1 — читать; 2 — не читать и не вычислять |
| `ifact` | использовать факторизованную AIC (0/1) |

Комментарий исходника описывает три режима:

1. AIC читается, параметры сингулярностей считаются: `nckaic=1, nckusp=0`;
2. читаются и AIC, и параметры: `nckaic=1, nckusp=1`;
3. читаются только параметры, AIC не считается: `nckaic=2, nckusp=1`.

```
$restart
 0.        0.
```

---

### 5.8. `$reference` (`$ref`)

**Карта 1:** `xref`, `yref`, `zref`, `nref`, `nprcof`.

| Поле | Значение |
|---|---|
| `xref, yref, zref` | точка приведения моментов |
| `nref` | в этой версии читается в локальную переменную и **не используется**; оставьте 0 |
| `nprcof` | формула Cp для сил: 1 — linear, 2 — slender, 3 — second order, 4 — isentropic (по умолчанию 3); допустимо 1…4 |

**Карта 2:** `sref`, `bref`, `cref`, `dref` — характерные площадь и длины.
Значения ≤ 0 заменяются на 1.

| Поле | Значение |
|---|---|
| `sref` | характерная площадь |
| `bref` | длина для момента относительно x |
| `cref` | длина для момента относительно y |
| `dref` | длина для момента относительно z |

```
$references for accumulated forces and moments
=xref     yref      zref
1.5       0.        0.
=sref     bref      cref      dref
20.40     6.        6.        6.
```

По умолчанию: `xref=yref=zref=0`, `sref=bref=cref=dref=1`, `nprcof=3`.

---

### 5.9. `$symmetry` (`$sym`)

**Карта 1:** `misym`, `mjsym`.

| Поле | Плоскость |
|---|---|
| `misym` | симметрия относительно плоскости x–z (y=0) |
| `mjsym` | симметрия относительно плоскости x–y (z=0) |

Значения флагов: 0 — симметрии нет, 1 — симметрия потока, −1 — антисимметрия
(см. печать `symmetry options` в `inputa`). `nsymm = |misym| + |mjsym|`:
0 — плоскостей нет, 1 — плоскость x–z, 2 — x–z и x–y. Для обычных задач
используются 0/1; −1 применяется для антисимметричных изображений.

```
$symmetry - xz plane of symmetry
=misymm   mjsymm
1.        0.
```

---

### 5.10. `$printout` (`$pri`)

**Карта 1:** `isings`, `igeomp`, `isingp`, `icontp`, `ibconp`, `iedgep`.

| Поле | Назначение |
|---|---|
| `isings` | печать интенсивностей сингулярностей на панелях; ≥3 включает карту сингулярностей |
| `igeomp` | печать геометрии сетей |
| `isingp` | диагностика сплайнов сингулярностей |
| `icontp` | диагностика расчётных точек (≥1 включает карту control points) |
| `ibconp` | печать граничных условий (≥1; ≥2 — карта BC) |
| `iedgep` | диагностика сопряжения кромок |

**Карта 2:** `ipraic`, `nexdgn`, `ioutpr`, `ifmcpr`, `icostp`, `indmap`.

| Поле | Назначение |
|---|---|
| `ipraic` | PIC-диагностика для указанной расчётной точки (0 — выкл.) |
| `nexdgn` | дополнительная диагностика |
| `ioutpr` | уровень вывода: вход −1/0/1 → внутренние 0/1/2 |
| `ifmcpr` | уровень вывода сил/моментов: −1/0/1 → 0/1/2 |
| `icostp` | печать стоимости (1 — вкл.) |
| `indmap` | отладочные карты индексов: 1 — `ispmap`, 2 — +`icpmap`, 3 — +`ibcmap`, ≥4 — `iextrp` |

Дополнительно: `icontp ≥ 1` или `ibconp ≥ 1` включают `icpmap`;
`ibconp ≥ 1` — `ibcmap`; `icontp ≥ 2`, `ibconp ≥ 2` или `isings ≥ 3` —
`ispmap`.

```
$printout options
=isings   igeomp    isingp    icontp    ibconp    iedgep
4.        0.        0.        1.        1.        0.
=ipraic   nexdgn    ioutpr    ifmcpr
.0        .0        1.        0.                  3.
```

(Во второй строке примера `icostp` пропущен, `indmap = 3`.)

---

### 5.11. `$velocity correction` (`$vel`) и `$bou`

**Карта 1:** `ivcorr`.

| Значение | Коррекция |
|---|---|
| 0 | нет |
| 1 | McLean |
| 2 | Boctor |

```
$velocity correction
=ivcorr
2.
```

`$boundary` (`$bou`) читает ту же одну карту (`ivcorr`) и дополнительно
включает генерацию входного файла для программы пограничного слоя
(`itapbl = 1`).

---

### 5.12. `$switches` (`$swi`)

**Карта 1:** `enx1`, `enx2`, `al1`, `al2`.

Секция допустима только при `amach > 1`; иначе — фатальная ошибка. Задаёт
порог/линейное смешивание коэффициента переключения граничного условия
«скорость ↔ массовый поток» в зависимости от наклона панели (common `/pincl/`).

```
$switches
0.9       1.1       0.        1.        
```

Обычно не требуется; значения по умолчанию `enx1=enx2=1`, `al1=al2=0`.

### 5.13. `$eat`

**Карта 1:** `epsgeo`, `igeois`, `igeout`, `nwxref`, `triint`, `iabsum`.

| Поле | Назначение |
|---|---|
| `epsgeo` | геометрический допуск для принудительных абутментов; 0 — автоматически при наличии `$pea` (0.001 от минимального диаметра, но не более 0.1) |
| `igeois` | <0 — не печатать входные абутменты |

| `nwxref` | >0 — подробная печать абутментов и их пересечений по сетям |
| `triint` | >0 — включить диагностику пересечения треугольников (`xtrint`) |
| `iabsum` | уровень печати абутментов: <0 — нет; 0 — только абутменты; 1 — +A.I.; 2 — +`nwprop`; 3 — +`iabutd` |

```
$eat - liberalized abutments

          0.        0.        0.        0.        1.
```

### 5.16. `$materials` (`$mat`)

**Карта 1:** `nprop` — число нестандартных материалов, 0…10.

Далее `nprop` карт:

```
tratio    pratio    имя
```

формат `2F10.0,A10`; нулевые отношения заменяются на 1.

Затем **карта:** `nsrfls` — число привязок материалов к поверхностям.

Далее `nsrfls` карт:

```
имя_сети  поверхность  имя_материала
```

формат `8A10`; `поверхность` — `upper` или `lower` (целиком строчными или
заглавными — смешанный регистр не принимается); материал — имя из списка
выше или его номер. Материал `air` (индекс 0) существует всегда.

```
$material properties
=nmat
1.
=tratio(1)pratio(1) mat-name(1)
1.        1.3       exhaust
=nmnet
3.
=netname  surface   mat-name
cowll     upper     exhaust
plume     lower     exhaust
base      upper     exhaust
```

Материалы позволяют моделировать струи/выхлоп с отношениями полного давления
и температуры. Если `pratio` ниже критического для заданного Mach, оно
поднимается до критического с предупреждением; при Mach < 0.01 свойства
принудительно сбрасываются на воздух.

## 6. Геометрия

### 6.1. Общий заголовок геометрической секции

Любая секция-генератор сетки (`$points`, `$quadrilateral`, `$gothic`,
`$circular`, `$elliptical`, `$trailing`) начинается с двух карт. Исключение —
`$cambered`: это модификатор последней созданной сети, у него этих двух карт
нет (см. 6.7).

**Карта 1** (формат `6F10.5`):

| Поле | Назначение |
|---|---|
| 1 | `kn` — **число сетей в этой секции** |
| 4 | `nedflk` — зарезервировано/отключено в этой версии |
| 5 | `imnwpr` — ≠0: печатать сетку сразу после генерации |
| 6 | `cpnorm` — режим нормалей панелей: −1 → 0 (старый, скорректированная геометрия); 1 → 1 (изогнутые нормали); 0/2/пусто → 2 (геометрия как задана) |

**Карта 2** (формат `6F10.5`):

| Поле | Назначение |
|---|---|
| 1 | `kt` — тип сети (см. таблицу 6.9) |
| 2…4 | зависят от `kt` (см. ниже) |
| 5 | `amnsw` — служебный флаг; 1 — транспонировать сгенерированную сетку |
| 6 | `dnsmsh` — ≠0: после геометрии **каждой** сети читать карту сгущения (см. 6.10) |

Затем идут `kn` описаний сетей в формате, определяемом секцией. Все сети
секции наследуют `kt` и остальные поля карты 2.

`$trailing` использует те же две карты, но описания сетей состоят из одной
карты каждое (см. 6.8).

---

### 6.2. `$points` (`$poi`) — координаты сетки

**Одна сеть:**

**Карта A** (формат `6E10.0,10X,A10`):

```
nm        nn                                                          netname
```

| Поле | Назначение |
|---|---|
| 1 | `nm` — число строк (точек в поперечном направлении) |
| 2 | `nn` — число столбцов |
| колонки 71–80 | имя сети |

**Карты координат:** для каждого столбца `j = 1…nn` — `ceil(nm/2)` карт;
на одной карте до двух точек (`x y z`), формат `6E10.0`. Порядок точек —
**по столбцам**: сначала все `m = 1…nm` для `n = 1`, затем для `n = 2` и т.д.

```
$points - wing-body  with composite panels
=kn                                               cpnorm
4.                                                2.
=kt
1.
=nm       nn                                                          netname
11.       3.                                                          winga
=x(1,1)   y(1,1)    z(1,1)    x(*,*)    y(*,*)    z(*,*)
   69.4737    9.2105    0.0000   63.7818    9.5807    0.7831
   ...
```

Внутренний индекс точки: `g = (j-1)*nm + (i-1)` (нумерация с нуля), где
`i` — строка, `j` — столбец. Именно так её понимает и C++-парсер
(`AeroModel::extractNetworks`, `pointAt(i,j)`).

Если карта 2 задаёт `dnsmsh ≠ 0`, после координат каждой сети читается
дополнительная карта:

```
col_factor   row_factor
```

(см. 6.10).

---

### 6.3. `$circular` (`$cir`) — тела вращения

**Одна сеть:**

**Карта A** (формат `E10.0,60X,A10`): `nopt` и имя сети (колонки 71–80).

* `nopt = 0` — тело без смещения по оси: `z(i) = 0`;
* `nopt > 0` — после радиусов читаются `z(i)` — смещения сечений вдоль оси.

**Карта B:** `nm` — число точек по образующей.

**Карты C:** `nm` пар `xs(i), ri(i)` — 3 пары на карту (`6E10.0`).

**Карты D** (только при `nopt > 0`): `nm` значений `z(i)`, 6 на карту.

**Карта E:** `nn` — число точек по окружности.

**Карты F:** `nn` значений `th(i)` в градусах, 6 на карту.

Генерируются точки:

```
x = xs(i)
y = ri(i) * cos(th(j))
z = z(i)  + ri(i) * sin(th(j))
```

Порядок: для каждого `j` (угол) — все `i` (образующая).

```
$circular sections - nacelle inlet
=kn
1.
=kt
9.
=nopt                                                                 netname
0.                                                                    inlet
=nm
4.
=xs(1)    ri(1)     xs(2)     ri(2)     xs(*)     ri(*)
2.        0.000     2.        1.328     2.        1.878
2.        2.300
=nn
5.
=th(1)    th(2)     th(3)     th(4)     th(5)
-90.      -45.      0.        45.       90.
```

Для `kt = 9` (inlet, total mass flux) после геометрии читаются карты `bet1`
для каждой внутренней расчётной точки — именно их и повторяет директива
`# 12 1` в `samples/nac6.inp`.

---

### 6.4. `$elliptical` (`$ell`) — эллиптические сечения

**Карта A:** `nopt`, имя сети.

**Карта B:** `nm`.

**Карты C:** `nm` троек `xs(i), ri(i), r2(i)` — 2 тройки на карту.

**Карты D** (при `nopt > 0`): `nm` значений `z(i)`, 6 на карту.

**Карта E:** `nn`.

**Карты F:** `nn` значений `th(i)`, 6 на карту.

Формулы:

```
den   = sqrt(r2(i)^2 * cos^2(th) + ri(i)^2 * sin^2(th))
y     = ri(i) * r2(i) * cos(th) / den
z     = z(i) + ri(i) * r2(i) * sin(th) / den
```

Примечание к исходнику: чтение `th` в `ellpt` организовано циклом по картам,
но массив читается целиком с каждой карты (`(th(i), i=1,n)`); практически
безопасно задавать не более 6 значений на карту.

---

### 6.5. `$quadrilateral` (`$qua`) — четырёхугольный препроцессор

**Карта A** (`6E10.0,10X,A10`): координаты углов 1 и 2
(`x1 y1 z1 x2 y2 z2`), имя сети в колонках 71–80.

**Карта B** (`6E10.0`): координаты углов 3 и 4.

**Карта C:** `nrow`.

**Карты D:** `nrow` значений `ypc(i)` — распределение по η (0…1), 6 на карту.

**Карта E:** `ncol`.

**Карты F:** `ncol` значений `xpc(j)` — распределение по ξ (0…1), 6 на карту.

Углы обходятся по порядку 1→2→3→4; билинейное преобразование квадрата в
четырёхугольник. Если хотя бы одна `z`-координата угла не нулевая, строится
простая скошенная поверхность линейной интерполяцией.

При `dnsmsh ≠ 0` после геометрии — карта сгущения (6.10).

---

### 6.6. `$gothic` (`$got`) — gothic / arrow / delta

**Карта A** (`6E10.0,10X,A10`): `ncol`, имя сети.

**Карты B:** `ncol` угловых точек `x y z`, по 2 точки на карту.

**Карта C:** `nrow`.

**Карты D:** `nrow` значений `ypc(i)`, 6 на карту.

**Карта E:** `ncen` — число точек вдоль центральной линии.

Далее сетка генерируется `gadnet`. При `dnsmsh ≠ 0` — карта сгущения.

---

### 6.7. `$cambered` (`$cam`) — camber/twist последней сети

`$cam` **не создаёт новую сеть и не читает `kn`/`kt`**. Он применяется к
последней уже созданной сети (обычно после `$quadrilateral`, у которой
угол 1 — вершина, а кромка 1 — центральная линия) и пересчитывает её
`z`-координаты по заданной срединной линии.

**Карта A** (`6E10.0,10X,A10`): `ntrl` и имя сети (колонки 71–80; имя
относится к уже существующей сети и перезаписывает её имя). `ntrl=1` — одна
срединная линия для всех сечений; `ntrl=2` — camber и twist меняются по
размаху.

При `ntrl=1`:

* **Карта B** (`6E10.0`): `npct`, `ncen`, `amnsw`.
* **Карты C:** `npct` значений `xpc` (x/c), 6 на карту.
* **Карты D:** `npct` значений `zpc(i,1)`, 6 на карту.

При `ntrl=2`:

* **Карта B** (`6E10.0`): `npct`, `ncen`, `amnsw`, `nyst`.
* **Карты C:** `npct` значений `xpc`, 6 на карту.
* Для каждого из `nyst` сечений по размаху: карта `ypc(i)` (одно значение),
  затем `npct` значений `zpc(i,j)`, 6 на карту.

`ncen` — число точек вдоль центральной линии (0 — использовать углы
предыдущей сетки). После пересчёта, как и для остальных секций, работает
карта сгущения при `dnsmsh ≠ 0` (см. 6.10). Если до `$cam` не было создано
ни одной сети, программа завершится ошибкой.

---

### 6.8. `$trailing` (`$tra`) — trailing wake

**Заголовок:** те же две карты. Для `kt = 18` поле 2 карты 2 — `matchw`
(0/1/2/3 — вариант условия сопряжения следа), поле 3 — `iwksrc`
(≠0 — след с источниками, «composite wake»). Для `kt = 19` поля 3/4 могут
переопределять `nlopt2`/`nropt2`.

**Одна сеть** — одна карта (формат `6A10,10X,A10`):

```
inat      insd      xwake     twake                                   netname
winga     1.        100.      .0                                      wingwk
```

| Поле | Назначение |
|---|---|
| `inat` | имя или номер сети, к кромке которой крепится след |
| `insd` | номер кромки 1…4 (см. 6.11) |
| `xwake` | x-координата downstream-конца следа |
| `twake` | 0 — след идёт параллельно оси x; 1 — вдоль направления невозмущённого потока |
| колонки 71–80 | имя новой сети следа |

Поля 5–6 зарезервированы/игнорируются. Координаты новой сети не задаются.
Сеть следа всегда имеет `nm = 2`, а `nn` равно числу точек вдоль кромки:
`nn(inat)` для кромок 1/3 и `nm(inat)` для кромок 2/4. Сеть `inat` должна быть
создана раньше (секция `$trailing` не может быть первой геометрической).

---

### 6.9. Типы сетей `kt`

Таблица восстановлена по диспетчеру `inbc` (`panair.f90:29948`). Для типов,
которые читают карты `bet1` на каждую внутреннюю расчётную точку, это
отмечено отдельно (подпрограмма `inbc2`).

| `kt` | Назначение (комментарий исходника) | Доп. данные |
|---:|---|---|
| 1 | indirect mass flux b.c. | — |
| 2 | thin wake | `tkw` в поле 2 карты 2; при `tkw=1` — `bet1` на внутренние точки |
| 3 | superinclined panels | — |
| 4 | inlets | `bet1` на внутренние точки |
| 5 | bases | — |
| 6 | off-body sources | — |
| 7 | source alone mass flux b.c. | — |
| 8 | direct mass flux b.c., composite networks | — |
| 9 | inlet b.c. with total mass flux | `bet1` на внутренние точки |
| 10 | **недопустим** | — |
| 11 | indirect velocity b.c., composite networks | — |
| 12 | thin wings, velocity b.c., doublets alone | `tkw` в поле 2; при `tkw=1` — `bet1` на внутренние точки |
| 13 | thin wing, simulated thickness, velocity b.c. | `bet1` на внутренние точки |
| 14 | superinclined (velocity) | — |
| 15 | inlets, velocity b.c. | `bet1` на внутренние точки |
| 16 | **недопустим** | — |
| 17 | source alone velocity b.c. | — |
| 18 | type 18 wake | см. 6.8 |
| 19 | type 6 design wake | `bet2` для точек передней кромки, если `abs(nropt2)` ∈ {1,7,8} |
| 20 | type 20 wake | — |
| 21 | doublets alone | — |
| 22…29 | **недопустимы** | — |
| 30 | arbitrary b.c. | третья карта с 6 кодами и, возможно, карты коэффициентов |

Для `kt = 30` карта 2 содержит `kt`, `ntsk`, `ntdk`, `ipotk`; затем читается
третья карта:

```
nlopt1   nropt1   nlopt2   nropt2   nlopt3   nropt3
```

После геометрии для каждой расчётной точки, у которой `nlopt=1`, читаются две
карты коэффициентов (по 6 значений), а для `abs(nropt)` ∈ {1,7,8} — карта `bet`.
Этот режим повторяет внутренний формат граничных условий; без необходимости
не используйте его.

Для `inbc2` (типы 4, 9, 13, 15, 2/12 при `tkw=1`) карта `bet1` читается для
каждой **внутренней** расчётной точки, т.е. `(nm-1)*(nn-1)` карт. Это
количество легко проверить по примеру `nac6`: у входа `nm=4`, `nn=5`,
`(4-1)*(5-1)=12`, что и соответствует `# 12 1`.

### 6.10. Сгущение сетки (`dnsmsh`)

Если в карте 2 последнего прочитанного геометрического заголовка поле 6
(`dnsmsh`) не нулевое, после геометрии **каждой** сети читается карта:

```
col_factor   row_factor
```

* первое число — коэффициент по столбцам (`nn`), второе — по строкам (`nm`);
* положительное `f` — разбить каждый интервал на `f` частей;
* отрицательное `-f` — наоборот, укрупнить в `f` раз.

Это относится ко всем геометрическим секциям (`$points`, `$quadrilateral`,
`$gothic`, `$cambered`, `$circular`, `$elliptical`, `$trailing`): в `meshp`
все ветви сходятся в метку `1000`, где и происходит сгущение. Для `$circular`
и `$elliptical` карта читается после генерации их сетки, для `$trailing` —
после генерации следа.

---

### 6.11. Нумерация кромок сети

Кромки нумеруются против часовой стрелки; `m` — строка (1…nm),
`n` — столбец (1…nn):

```
(nm,1) <──── кромка 3 ──── (nm,nn)
  ↑                            ↓
кромка 4                     кромка 2
  ↑                            ↓
(1,1)  ──── кромка 1 ────>  (1,nn)
```

* кромка 1: `m=1`, от `n=1` к `n=nn`;
* кромка 2: `n=nn`, от `m=1` к `m=nm`;
* кромка 3: `m=nm`, от `n=nn` к `n=1`;
* кромка 4: `n=1`, от `m=nm` к `m=1`.

Эта нумерация используется в `$abutments`, `$pea`, `$trailing`.

## 7. Абутменты и преобразования геометрии

### 7.1. `$abutments` (`$abu`)

**Карта 1:** `nabut` — число абутментов.

**Карты 2 (по одной на абутмент):** фиксированный формат `A10,F10.0,A10,F10.0`:

```
net1      edge1     net2      edge2
winga     4.        bodyl     2.
```

* `net1`, `net2` — имя (10 символов) или номер сети;
* `edge1`, `edge2` — номера кромок 1…4.

Секция должна идти после всей геометрии: имена сетей к этому моменту уже
известны. Для поиска используется текущий список имён (`nwname`).

---

### 7.2. `$pea` — частичные/полные абутменты кромок

Может встречаться несколько раз.

**Карта группы:** `nfpa`, `iopfor`, `movusr`.

| Поле | Значение |
|---|---|
| `nfpa` | число спецификаций в группе |
| `iopfor` | метод форсирования: 0 — обычный, 1 — усреднение в классе эквивалентности |
| `movusr` | уровень печати: <0 — нет; 0 — обычный; ≥1 — печатать z до/после |

**Для каждой спецификации:**

**Карта:** `nne`, `peatol`.

* `nne` — число кромок в спецификации (≤10);
* `peatol` — допуск; если ≤0, берётся 1e-4 (или допуск предыдущей спецификации).

**Карты кромок (nne штук):** формат `A10,3F10.0`:

```
network   edge      first_pt  last_pt
winga     4.        6.        1.
```

* `network` — имя или номер сети;
* `edge` — кромка 1…4;
* `first_pt`, `last_pt` — индексы точек вдоль кромки (порядок нормализуется:
  меньшее значение становится первым).

```
$pea - partial or full network edge abutments
=nfpa     iopfor    movusr
2.        0.          2.
=nne      peatol
2.        .005
=nn       en        epinit    eplast
winga     4.        6.        1.
bodyl     2.        5.        9.
2.
winga     4.        6.        11.
bodyu     4.        7.        3.
```

### 7.3. `$rearrange` (`$rea`) — поворот/масштаб/сдвиг

**Карта 1:** `nrearr` — число преобразований.

Для каждого преобразования:

**Карта:** `ntr`:

| `ntr` | Преобразование | Следующие карты |
|---:|---|---|
| 1 | поворот вокруг прямой | `k1 k2`; `x1 y1 z1 x2 y2 z2` (две точки оси); `phi` (градусы) |
| 2 | поворот вокруг точки по трём осям | `k1 k2`; `phi1 phi2 phi3 ord1 ord2 ord3`; `x1 y1 z1` |
| 3 | масштаб | `k1 k2`; `sx sy sz` (0 заменяется на 1) |
| 4 | сдвиг | `k1 k2`; `dx dy dz` |

`k1…k2` — диапазон номеров сетей (включительно). В `ntr=2` поле `ord1…ord3`
задаёт порядок поворотов: 1 — вокруг x, 2 — вокруг y, 3 — вокруг z.

## 8. Выбор сетей для сил/моментов и сечений

### 8.1. `$forces` (`$for`)

Секция задаёт список сетей/поверхностей для накопления сил и моментов.

После `$for` читаются **только** карты-маркеры, начинающиеся с `*`; первая
карта, не являющаяся маркером (обычно следующий `$...`), завершает секцию.

**Маркер `*net`** (в т.ч. `*network ...`). Следующая за маркером карта:

```
nosnet    icomop
```

| Поле | Значение |
|---|---|
| `nosnet` | >0 — включить перечисленные сети; <0 — исключить перечисленные; 0 — все сети |
| `icomop` | 0 — «composite» сети всегда включены, список добавляет/исключает остальные; 1 — список задаёт набор ровно |

Далее `|nosnet|` карт с номерами сетей (по одной на карту).

Поведение по умолчанию (`isignl = 0`, список не задан): в силы включаются
сети, помеченные как composite (в этой версии — сети `kt=1`); сети-следы
типов 18 и 20 исключаются автоматически, так как не имеют этого флага.

**Маркер `*pre`** (в т.ч. `*pressure`). Следующая карта:

**Карта:** `numscd` — число сетей с явно заданной поверхностью.

Далее `numscd` карт:

```
network   surface_code
```

* `surface_code`: 1 — upper, 2 — lower, 3 — difference (разность);
* 0 заменяется на 1.

Пример (`samples/btac.inp`):

```
$forces and moments summary for nonwake networks
*pressure
3.
=234567890
1.        1.
2.        1.
3.        3.
```

---

### 8.2. `$sectional properties` (`$sec`)

**Карта 1:** `numgrp` — число групп сечений (≤5).

Для каждой группы читаются маркеры `*net` / `*pre` / `*cut`
(допускаются и варианты `$net` / `$pre` / `$cut`, т.к. префикс проверяется
одинаково). Секция заканчивается, когда встречается карта, не являющаяся
маркером (следующая `$...`).

**`*net`:**

* `numnet` — число сетей; >0 — включить список, <0 — исключить, 0 — все;
* далее `|numnet|` карт с номерами сетей.

**`*pre`:**

* `numscd` — число сетей с явной поверхностью;
* далее `numscd` карт: `network surface_code` (1 upper, 2 lower, 3 difference).

**`*cut`.** Следующая карта — параметры (формат `7F10.5`):
`optcrd`, `optmrp`, `iprtnf`, `iprtpp`, `isecpr`, `ixyzop`, `reflen`.

| Поле | Значение |
|---|---|
| `optcrd` | 0 — хорда по выбранной оси (`ixyzop`) между min/max сечения; 1 — между min/max точками 3D-сечения; 2 — задать хорду вручную |
| `optmrp` | 0 — точка приведения `xref,yref,zref`; 1 — доля хорды `refrac`; 2 — `xc,yc,zc` данного сечения |
| `iprtnf` | печать данных по силам сечений |
| `iprtpp` | печать данных по давлениям сечений |
| `isecpr` | диагностическая печать (обычно 0) |
| `ixyzop` | ось для расчёта хорды: 1 — x, 2 — y, 3 — z |
| `reflen` | характерная длина группы (`refeta`), нормирующая `eta` |

**Карта:** `numcut` — число сечений (≤25).

Для каждого сечения:

**Карта:** `xc yc zc xcn ycn zcn [eta]` — точка на плоскости сечения и
нормаль к ней; необязательное 7-е значение `eta` — координата размаха для
коэффициентов сечения (если задан и `reflen`, используется `eta/reflen`).

Если `optcrd = 2` или `optmrp = 1`, далее читается карта:

```
chrd    refrac
```

* `chrd` ≤0 → 1; `refrac` ≤0 → 0.25;
* при `optcrd=2` значение `chrd` используется как хорда;
* при `optmrp=1` `refrac` используется как доля хорды для точки приведения.

Пример (`samples/swb.inp`):

```
$sectional properties
=numgrp
1.
*network selection for sectional properties
=numnet
2.
=netdat
1.
2.
*cut and reference printout for sectional properties
=optcrd   optmrp    iprtnf    iprtpp    isecpr    ixyzop    reflen
1.        1.        0.        0.                            30.
=numcut
2.
=xc       yc        zc        xcn       ycn       zxn
.0        15.       .0        .0        1.        .0
=chrd     refrac
          .25
.0        25.       .0        .0        1.        .0
          .25
```

### 9.2. `$grids` (`$gri`) — прямоугольная сетка точек в поле

**Карта 1:** `ngt` — число сеток.

Для каждой сетки — **три карты по 6 значений** (формат `6F10.5`):

| Карта | Поля |
|---|---|
| 1 | `ox oy oz` (начало координат) + `xx xy xz` (точка на оси x) |
| 2 | `yx yy yz` (точка на оси y) + `zx zy zz` (точка на оси z) |
| 3 | `dx dy dz` (шаги) + `ix iy iz` (число точек; 0 → 1) |

Оси задаются **точками в абсолютных координатах**; `gridgn` вычитает начало
координат и нормирует. Порядок генерации: `i` (x) — внешний, `j` (y) —
средний, `k` (z) — внутренний. Всего точек — `ix*iy*iz`; суммарно по `$xyz`
и `$grids` допускается не более 1666 точек.

```
$grid - offbody points entered as a grid of points
=ngt
1.
=ox       oy        oz        3x        3y        3z
85.0      22.5      -7.5      95.0      22.5      -7.5
=2x       2y        2z        1x        1y        1z
85.0      37.5      -7.5      85.0      22.5      7.5
=d3       d2        d1        i3        i2        i1
5.        5.        5.        1.        4.        4.
```

(Здесь `ix=1`, `iy=4`, `iz=4`.)

**Карты 2:** номера сетей, 6 на карту.

### 9.4. `$streamlines` (`$str`)

**Карта 1:** `nstmln` — 0 — не считать линии тока; ≠0 — считать.

Если `nstmln ≠ 0`:

**Карта 2** (формат `6F10.5`): `numpts`, `hmin`, `hmax`, `maxstm`, `maxordr`,
`abserr`.

| Поле | Значение | По умолчанию |
|---|---|---|
| `numpts` | число линий тока (≤500) | 0 |
| `hmin` | минимальный шаг | 1e-7 |
| `hmax` | максимальный шаг | 10000 |
| `maxstm` | макс. число точек интегрирования на линию (≤1000) | 1000 |
| `maxordr` | максимальный порядок интегрирования (≤6) | 6 |
| `abserr` | допустимая ошибка шага | 1e-6 |

**Карта 3** (формат `7F10.5`): `maxarr1`, `isprnt`, `tpsl`, `irhssl(1..4)`.

| Поле | Значение |
|---|---|
| `maxarr1` | размер рабочего массива (по умолчанию 10000) |
| `isprnt` | печать файла линий тока (1 — печатать) |
| `tpsl` | 0 — массовый поток; иначе — скорость |
| `irhssl(1..4)` | номера решений, для которых считать линии тока; 0 — не задано |

Если ни одно решение не выбрано, используется первое.

Далее для каждой линии тока — **две карты**:

1. `x y z dx dy dz` — начальная точка и максимальные приращения;
2. `fwdbk` — 0 — интегрирование вперёд, ≠0 — назад.

```

10000.    0.        0.        1.
=x        y         z         dx        dy        dz
.01       0.        -2.28     3.        2.        2.
=fwdbk
-1.
.27       0.        -2.34     3.        2.        2.
-1.
```

## 11. Частые ошибки

1. **Данные на строке с `=`.** Строка `=amach 0.6` — целиком комментарий;
   значение потеряется. `=` — только подпись, значение на следующей карте.
2. **Смешанный регистр ключа.** `$Symmetry` не распознается: сравниваются
   только полностью строчный и полностью заглавный варианты.
3. **Значимые первые 4 символа.** `$my_points` не является `$poi`; ключ
   должен начинаться с `$poi`.
4. **`$title` без второй строки.** Следующая секция будет съедена как вторая
   строка заголовка.
5. **Числа не в 10-символьных полях.** Строка `1 2 3` в секции с `6E10.0`
   даст не те значения или ошибку чтения; выравнивайте по 10 колонкам.
6. **`#` в данных.** Карта, начинающаяся с `#`, — директива повторения, а не
   значение. В координатах `#` не использовать.
7. **`kn` — это количество, а не номер.** Сумма `kn` по геометрическим
   секциям должна совпадать с `$net`, если `$net` задан.
8. **`$abutments`/`$pea` до геометрии.** Имена сетей ещё не известны —
   программа завершится ошибкой.
9. **`$abc`** — любой неизвестный ключ фатален; список допустимых — в
   разделе 4.
10. **Экспонента в `F10.x`-секциях.** В `$mach`, `$reference`, `$printout`,
    `$angles` и т.п. используйте обычную десятичную запись.

## 12. Замечания для C++-переписывания (`src/A502lib/AeroModel.cpp`)

Текущий C++-парсер устроен иначе, чем оригинал; при сверке полезно помнить:

* `AeroModel` разбирает **все** секции в список `Section`/`Entry`, а не только
  известные, и сохраняет `=name` как объявления. Оригинал `=`-строки
  **выбрасывает**. Из-за этого C++-парсер «видит» больше, но не всегда так,
  как Fortran.
* C++-парсер считает `#` обычными данными, а оригинал — директивой повторения.
  Для deck'ов без `#` в координатах это не мешает; для `# 12 1` из `nac6`
  поведение отличается.
* C++-парсер извлекает сети только из секций `$points`. Оригинал также умеет
  `$quadrilateral`, `$gothic`, `$circular`, `$elliptical`, `$trailing`, а
  также модификатор `$cambered`; для них нужны отдельные генераторы.
* Ключ секции в C++ нормализуется (нижний регистр, удаление не-алфавитно-
  цифровых), а оригинал сравнивает **первые 4 символа**. Поэтому
  `findSection("points")` в C++ и `$poi` в Fortran — не одно и то же правило.
* В C++ координаты сети хранятся в `Network::coordinates` в порядке
  `g = j*nm + i`; это совпадает с порядком `$points` в оригинале.
* C++-парсер извлекает `kn`/`cpnorm`/`kt` эвристически из числовых токенов
  перед первым именем сети. В оригинале `kt` — 1-е поле второй карты, а
  `cpnorm` — 6-е поле первой. В deck'ах с дополнительными полями (например,
  `ellip.inp`) эвристика может дать неверные `kt`/`cpnorm`.
* Для сетей с дополнительными картами `bet1` (`kt=4/9/13/15`) C++-экстрактор
  `$points` может принять числа `bet1` за координаты: он собирает все числа
  после имени сети до следующего имени.
